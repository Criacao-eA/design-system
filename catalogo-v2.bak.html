O sistema visual da e-Auditoria, num lugar só.

Tokens, primitivos e blocos prontos para landing pages (WordPress + HubSpot) e newsletters — com preview ao vivo e código para copiar. Uma fonte única, controlada pela Criação, para toda peça sair consistente e escalar sem retrabalho.

Como usar. Cada bloco tem preview e código. Clique em Copiar, cole na peça e troque o conteúdo. Para web, carregue os tokens (eauditoria-tokens.css) e as fontes uma vez no topo — e prefixe tudo com o wrapper da peça. Para e-mail, os valores vão inline (Outlook não entende variáveis). Nota: no preview as fontes aparecem via fallback do sistema — em produção, o @import traz Familjen Grotesk + Manrope de verdade.
O que mudou na v3. O catálogo deixou de ser só de componentes e passou a cobrir a identidade: entraram Uso da marca (com o vetor do logotipo, que não existia — os arquivos de origem eram PNG de 641px), Sub-marcas, Mascotes, as 6 paletas por vertical extraídas por amostragem das artes oficiais, e as superfícies — Padrões, Backgrounds e Vidro. Os ícones foram separados em 2D e 3D. Onde há vetor, o botão de download gera o PNG na hora, em qualquer tamanho.
Da v2. As regras aprendidas na publicação de 29/07/2026, quando uma página subiu sem estilo por três causas independentes, estão em Governança (14 regras) e no Pré-voo. Cada bloco com armadilha conhecida traz o aviso no próprio card; onde há decisão de conversão, há nota de CRO.

Duas regras que custaram caro (29/07/2026).
1 · Cor de texto em <a> precisa de !important. O tema tem .inside-article a{color:initial !important}, que vence qualquer especificidade. Sem o !important, os CTAs computavam preto puro em vez de #050634.

Contador animado

WebNovo na v2

Números que sobem quando entram na tela. A regra que faz ele ser seguro: o valor final já está escrito no HTML — o JS só o substitui para animar. Sem JS, o número correto continua lá.

Counter com fail-safe

data-count
210.000
CNPJs auditados
<!-- o número JÁ vem certo no HTML: se o JS não rodar, nada se perde -->
<b class="ea-count" data-count="210000">210.000</b>

// requestAnimationFrame, sem "e comercial" duplo (proibido no bloco WP)
var els = document.querySelectorAll('[data-count]');
els.forEach(function (el) {
  var alvo = parseInt(el.getAttribute('data-count'), 10);
  if (isNaN(alvo)) { return; }
  var t0 = null, dur = 1200;
  function passo(t) {
    if (t0 === null) { t0 = t; }
    var p = Math.min((t - t0) / dur, 1);
    var e = 1 - Math.pow(1 - p, 3);               // ease-out cúbico
    el.textContent = Math.round(alvo * e).toLocaleString('pt-BR');
    if (p < 1) { requestAnimationFrame(passo); }
  }
  requestAnimationFrame(passo);
});

toLocaleString('pt-BR') é obrigatório: sem ele o número sobe como 210000 em vez de 210.000. Para moeda, formate com {style:'currency',currency:'BRL'}.

CRO — o que já nasce visível NÃO ganha fade. Título, subtítulo e CTA do hero recebem .is-instant e entram prontos. Fazer o conteúdo que a pessoa veio ver aparecer com transição atrasa o LCP percebido e empurra o CTA para depois da primeira impressão. Reveal só faz sentido abaixo da linha d'água.

Gancho com segunda via. Todo JS de bloco WordPress começa procurando o wrapper por id e por class, e sai sem erro se não achar nenhum dos dois. Foi exatamente aqui que um script inteiro abortou em silêncio quando o sanitizador apagou os atributos do wrapper.

Camada 0 · o que não se negocia

Regras

Sete destas regras vieram do repertório da casa. As outras sete foram aprendidas em 29/07/2026, quando o hero do site subiu completamente sem estilo — botão virado em link sublinhado, SVGs de 340px, texto em degradê invisível. Três causas independentes, e nenhuma delas era o CSS estar malformado.

Governança

Obrigatório

O que faz um bloco funcionar ou quebrar em produção.

01

Nada de && no JS do WordPress

O editor recodifica o caractere dentro de script e derruba o arquivo inteiro — vale até dentro de comentário. Use if aninhado ou guard clause. Se o & for mesmo necessário, monte-o com String.fromCharCode(38).

02

Escopo por wrapper único

Todo CSS prefixado por um id/classe da peça. Nunca seletor global (body, .card solto). É o que isola a peça do tema.

03 · novo

Nenhum data-* no wrapper de escopo

O sanitizador do WordPress apaga data-* do conteúdo salvo — e nesse elemento levou class e id junto. Sem a classe, 91 regras morreram de uma vez. A forma que sobrevive é só class e id. data-* criado por JS em runtime é seguro.

04 · novo

Estado normal não depende de atributo

Uma regra como .ea-lp[data-fx="on"] .hero{…} nunca aplica em produção. O comportamento padrão vira a regra base; o atributo fica só como válvula de escape no mockup.

05 · novo

Prefixo também dentro de @media

Media query não soma especificidade. .ea-lp .hero (0,2,0) vence @media{.hero} (0,1,0) — e a override morre calada. Se o componente foi declarado prefixado, toda override dele leva o mesmo prefixo, em qualquer lugar.

06 · novo

Cor de <a> com !important

O tema tem .inside-article a{color:initial !important}, que vence qualquer especificidade. Corolário de design: botão sobre fundo escuro não pode depender de texto claro — use fundo âmbar com texto navy.

07 · novo

Arquivo de entrega sem comentário

Um */ órfão engoliu um bloco @media inteiro, em silêncio. Comentário é a parte mais frágil do que se cola — e é ruído para quem cola. Explicação e histórico vão para documento à parte.

08 · novo

@import na linha 1

Nada acima dele, nem comentário: o editor promove o @import ao topo e descarta o que estava antes. E @import só vale antes de qualquer outra regra — depois de um seletor, o navegador ignora em silêncio e a tipografia desaba.

09

Fail-safe sem JS

Conteúdo e números pré-preenchidos no HTML; o JS só adiciona animação. Com WP Rocket ou Perfmatters adiando scripts, a página precisa continuar completa. Única exceção conhecida: o player de vídeo.

10

Captura sempre por HubSpot

Embed do portal da e-Auditoria. Nunca form próprio postando no CRM, nunca chave de API no front. Confira o data-form-id antes de publicar.

11

E-mail é tabela, não flexbox

Layout por <table>, estilos inline, larguras fixas, gradiente sempre com bgcolor sólido de fallback.

12

Um CTA amarelo por dobra

Amarelo só no botão de ação, texto escuro. Se tudo destaca, nada destaca.

13 · novo

Validar no ar, não no preview

O painel de pré-visualização do editor renderiza sem aplicar as abas por completo. Só a página publicada diz a verdade — e é lá que se roda a checagem do pré-voo.

14 · marca

Expressões que nunca quebram linha

e-Auditoria — nunca por hífen nem por quebra entre "e-" e "Auditoria". E também: Simples Nacional, Simples Híbrido, Lucro Real, Lucro Presumido, Reforma Tributária. Envolver em <span class="ea-nb">.

15 · marca

Sempre e-A, nunca ë-A

O trema existe no desenho do logotipo, não na palavra escrita. Em texto corrido: e-A e e-Auditoria. E sempre que o nome aparecer sozinho — cabeçalho, rodapé, assinatura, selo, rótulo — use o logotipo, não a palavra. A palavra escrita só sobrevive dentro de uma frase.

16 · marca

Sub-marca não carrega a marca-mãe

Não existe lockup Sub-marca | e-Auditoria. Toda sub-marca é autossuficiente. A assinatura só entra junto quando a solicitação de produção pedir explicitamente.

17 · marca

Iniciais maiúsculas, mesmo sozinhas

"o Simples", "a Reforma" — são nomes próprios do domínio fiscal, não adjetivos. Minúscula só quando a palavra for mesmo o adjetivo ("de forma simples").

18 · cor

Marca-mãe fala em azul

Quando o assunto é a e-Auditoria, a paleta é azul e, no máximo, lilás. Pink, laranja e magenta só quando o assunto for uma sub-marca ou vertical que os tenha.

Design system não é só consistência visual — é também não repetir erro de conversão. O que segue vale para landing page de campanha da e-Auditoria, com o público e o volume que temos.

Princípios que já valem para o próximo projeto

Amostra pequena não sustenta teste pequeno

LP B2B de nicho não dá significância para testar cor de botão em três semanas. Priorize mudanças grandes (efeito legível com pouca amostra) e método qualitativo — gravação de sessão, mapa de calor, cinco entrevistas com contador.

O calendário manda

Campanha com janela fiscal tem data de congelamento. Teste que precisa de três semanas começa na primeira semana, não na terceira — e perto do pico não se mexe na página que está convertendo.

Copy com prazo tem data de morte

Quando a janela fecha, contador de dias e "sobre a janela de setembro" viram erro factual. Programar a versão pós-janela é manutenção obrigatória, não teste — e ela bate justamente quando a página começa a ranquear.

CTA repetido demais anestesia

Dezesseis CTAs quase idênticos para a mesma âncora deixam de ser lidos. Menos CTAs, em pontos de scroll medido, com verbos distintos. Olhe clique bruto e conversão juntos: menos clique com mais conversão é vitória.

Prova concreta bate argumento

Um gráfico que mostra o mecanismo vale mais que quatro dobras afirmando que ele existe. Se a página tem um ativo assim enterrado no meio, subir é a hipótese mais barata da lista.

Número inventado custa confiança

Para contador — o público mais numérico que existe — valor ilustrativo que não bate com a realidade dele vira objeção. Um caso real anonimizado ("escritório de Vitória/ES, carteira de 180 CNPJs") converte melhor e reduz risco.

Mobile primeiro na hora de validar

Se a maior parte do tráfego é mobile, otimizar desktop primeiro é otimizar o lugar errado. Abrir em aparelho real é pré-requisito, não teste.

Um teste por vez

Com esse volume, dois testes simultâneos na mesma página tornam os dois ilegíveis.
